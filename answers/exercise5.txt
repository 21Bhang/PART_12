Exercise 5 - Containerizing a Node application (todo-backend)
=============================================================

Imaged the todo-backend Express app.

$ docker build -t todo-backend .
[+] Building ... FINISHED
#8 [4/4] RUN npm ci --omit=dev
#8 added 124 packages, and audited 125 packages in 17s
#9 exporting to image
#9 naming to docker.io/library/todo-backend:latest

$ docker run -p 3000:3000 todo-backend
> todo-express-backend@0.0.0 start
> node ./bin/www

$ curl -s http://localhost:3000/
{"visits":1}

$ curl -s http://localhost:3000/
{"visits":2}

Dockerfile follows the course best practices: node:24 base, WORKDIR /usr/src/app,
COPY --chown=node:node, RUN npm ci --omit=dev, USER node, CMD ["npm", "start"].
node_modules and .env are kept out of the image via .dockerignore.

Follow-up: wiring env files (docker-compose + docker run)
---------------------------------------------------------

.env (local, gitignored, not committed - same convention as upstream):
MONGO_URL=mongodb://the_username:the_password@localhost:3456/the_database
REDIS_URL=redis://localhost:6379

app loads .env natively:
$ npm start
> node --env-file-if-exists=.env ./bin/www

warm up mongodb + redis for development (mongo-init.js bind mounted, seeds todos):
$ docker compose -f docker-compose.dev.yml up -d
$ curl -s http://localhost:3000/
{"MONGO_URL":"mongodb://the_username:the_password@localhost:3456/the_database","REDIS_URL":"redis://localhost:6379","visits":1}

$ curl -s -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"text":"Containerize with Dockerfile"}'
